# Decisions

Every deviation from the execution spec is recorded here with its reason.

## 2026-10-27 (Day 1)

| # | Decision | Reason |
| --- | --- | --- |
| 1 | Folders are named by role: `backend/` (spec: `app/`) and `frontend/` (spec: `web/`). | Owner preference for role-based names. |
| 2 | Hosting is the owner's Dokploy VPS, project `karhutla`, not a Compute Engine VM. | The owner already runs Dokploy; Traefik there provides HTTPS and domains. |
| 3 | Caddy is dropped. | Dokploy's Traefik terminates TLS with Let's Encrypt. |
| 4 | SQLite lives on a Dokploy named volume mounted at `/data`. | Persistent disk without a managed database. |
| 5 | Citizen channel is WhatsApp Cloud API plus a web form at `/lapor`, not Telegram. | WhatsApp is part of the Meta ecosystem. The web form lets judges try reporting, since a WhatsApp test number only reaches up to 5 registered recipients. |
| 6 | Provider switches `LLM_PROVIDER` and `ASR_PROVIDER` (`meta` or `assemblyai`). | The Meta Model API credit is pending approval. AssemblyAI is an interim and fallback provider only. Demo, video, and evaluation run on Meta models. |
| 7 | Map starts on MapLibre with OpenStreetMap tiles. The Google Maps adapter is not built yet. | No Google Maps key yet. `MAP_PROVIDER=google` currently shows a visible note and falls back to MapLibre. |
| 8 | Fixture mode is the default and marks every incident as `simulation` (SIMULASI badge). | Day 1 builds without the Meta key. Fixture data is real FIRMS, Open-Meteo, and Overpass responses captured on 2026-10-26 for a cluster near -0.02, 116.45 (East Kalimantan). |
| 9 | The evidence gate (`backend/gate.py`) is built on Day 1 instead of Day 6. | It is deterministic code that needs no model, so it can be tested now. The critique pass (second Muse Spark call) still lands on Day 6. |
| 10 | Dashboard UI text is English; dispatch briefs are Indonesian and English. | Judges are global. Open to change. |
| 11 | Basemap is OpenFreeMap Positron (vector, no key) instead of raw OpenStreetMap raster tiles. | A muted basemap keeps fire data legible and looks professional. It also avoids leaning on the OSMF tile servers. |
| 12 | Map severity comes from measured FIRMS values: color follows fire radiative power (MW), opacity follows detection confidence. | No model-made severity score, consistent with spec principle 3. |
| 13 | A drone survey simulator is added (Blender 3D flyover, Muse Glimmer frame filter on the drone, SAM 3.1 on the server), planned for Days 5 and 6. Google Maps, the peat layer, and Muse Wonder are cut to make room. | Lets the agent close its own uncertainty by requesting a survey. Blender renders give exact ground-truth masks for measuring area error. All drone output is labelled SIMULASI. |

## 2026-10-27 (Day 2)

| # | Decision | Reason |
| --- | --- | --- |
| 14 | OSM is fetched per 0.2 degree tile (padded 0.1 degree, 0.3 for fire stations), cached 7 days, with at most 12 uncached tiles per run and three Overpass endpoints tried in order. | On 2026-10-27 all four public Overpass endpoints tried returned 502, 504, or timed out, and overpass-api.de states it is meant for human-operated use. One tile serves every incident inside it. |
| 15 | Automatic enrichment covers citizen reports and clusters with 3+ hotspots or max FRP 20 MW and above; a verifier can collect any incident on request. | Open-Meteo allows under 10,000 calls a day and Overpass is shared. Most clusters are single hotspots. |
| 16 | A failed or deferred source is stored as `failed: reason` and shown in the UI as UNKNOWN, then retried; retries never duplicate evidence. | Spec principle 5 and global rule 18. |
| 17 | In fixture mode, weather and OSM are recorded as unknown outside 15 km of the fixture point. | Fixture values from one place must not be presented as facts about another. |
| 18 | Evidence type `report` is added for the citizen's typed description. | The spec lists seven types and none fits free text. |
| 19 | `/lapor` is in Indonesian; the dashboard stays in English. | Reporters are Indonesian residents; dashboard readers include global judges. |
| 20 | Verifier endpoint `DELETE /api/incidents/{id}/citizen-data` removes citizen text, photos, voice, and files. | Needed for the retention promise in SAFETY.md and to remove test reports from production. |
| 21 | Triage runs only on purpose. A verifier ticks incidents or draws an area on the map (the box keeps the highest-FRP incidents up to 5 per selection) and confirms with an execution code. Wrong codes lock a client out after 5 attempts for 15 minutes. A server-side cap of 30 runs per WITA day covers manual and scheduled runs. The schedule is stored in the database: daily by default, hourly as high intensity, or off, and it only triages citizen-reported incidents. | Each triage spends about $0.05 of Meta credit (measured). Automatic triage over all 400+ eligible clusters would have used most of the credit before judging. |
| 22 | The interface is bilingual, Indonesian by default, with an ID or EN switch on every page. Dashboard text is written in English with an Indonesian dictionary; the report page is written in Indonesian with an English one. Server-generated text (evidence summaries, gate reasons, claims written by the model) stays in English, and report errors from the server stay in Indonesian. | Operators and residents read Indonesian; judges read English. |
| 23 | Three NASA GIBS daily layers are available on the map: VIIRS true color, MODIS aerosol optical depth, and the OMPS UV aerosol index, with NASA's own color legends. They are display only and are not used as evidence. | GIBS serves colored image tiles, not values, so the gate cannot check numbers from them. Clouds also hide smoke. |
| 24 | Sentinel-2 L2A comes from Earth Search (Element 84, AWS open data), read as Cloud Optimized GeoTIFF windows with Rasterio. Planetary Computer is not used. | On 2026-10-28 the Planetary Computer STAC search returned HTTP 504 on four of five search calls; Earth Search answered every call in under a second with the same scenes, including the 25 October pass. Rasterio 1.5.2 ships wheels with GDAL for Python 3.15, so the image needs no system GDAL. |
| 25 | Pair rule: the after image is the newest scene since the first detection that is at least 60% clear over the area of interest (scene classes dark area, vegetation, bare, unclassified); the before image is the newest such scene 2 to 120 days before it, in the same UTM zone. The area of interest is the hotspot box plus 750 m, between 1 and 5 km from the center. | Fires often start before the first hotspot, so the before image keeps a 2 day gap. "Dark area" is kept as clear because fresh burn scars are often classified there. |
| 26 | Burned hectares = 20 m pixels clear in both images with dNBR at or above 0.27 (USGS moderate-low severity), times 0.04 ha. Pixels from 0.10 to 0.27 are reported as low severity and never counted as burned. The gate recomputes the area from the stored pixel count and sets the method to dnbr. | A fixed published threshold that code applies is checkable; a model estimate is not. |
| 27 | If either image has a median aerosol optical thickness above 0.8, the pair is stored as hazy: images and dNBR statistics are kept, but no pixel count is passed on, so no hectares can be claimed. | The 23 October scene over Merauke was classified 99.8% clear yet sat under thick smoke (AOT 0.99). Smoke lowers NIR, which inflates dNBR. |
| 28 | Satellite pairs are fetched only on request: by the agent's `get_satellite_pair` tool during a triage or by a verifier button. A stored pair is reused for 24 hours. Images are public at `/api/satellite/{incident}/{file}`. | Each pair reads about 20 windows (10 to 30 s). Sentinel-2 passes about every 5 days, so checking more often repeats the answer. It is open data, unlike citizen media. |
| 29 | The drone survey is a simulation over a real incident: INC-20261025-0407 (East Kalimantan). Blender 5.2 renders the ground from that incident's real Sentinel-2 after image and dNBR burn mask, with procedural canopy, char, active fire at the newest FIRMS hotspots, and smoke leaning downwind from the stored Open-Meteo wind. The mission comes from the app's own planner (`backend/drone.py`): lawnmower, 120 m above ground, 1 inch camera, GSD 0.176 m, 48 frames over 0.76 km2. Code is in `sim/`, frames in `replay/drone/`. | A real drone flight is out of reach before the deadline. Anchoring the scene on real satellite data keeps the geometry and the burn shape real; only the pixels are synthetic. |
| 30 | Muse Glimmer runs at the ground station, not on the drone: llama.cpp (official CUDA image) serving the 17 GB Q4_K_M GGUF with its vision projector on a Modal A10G (`edge/glimmer_modal.py`). It decides per frame which to uplink. | Glimmer is a dense 30B model; even the quantized build needs a 24 GB class GPU. Claiming it runs on a small drone would be false. |
| 31 | Drone results are shown beside the incident as SIMULASI and never stored as its evidence, so triage can not quote them. | A real dispatch brief must not carry a hectare figure that came from a render. |
| 32 | SAM concept on drone frames is "bare ground", and hectares count only frames where SAM returned a mask. | On nadir frames SAM returned nothing for "burned ground", "ash", "forest", "tree", "ground", "soil", "burnt area", "scorched earth", and "dead tree"; "bare ground" matched the truth at IoU 0.92 on an edge frame. On frames burned edge to edge it returns no mask, and an orthomosaic did not help either. Reporting those frames as not measured is honest; treating them as zero or as fully burned would not be. |
| 33 | Operator settings live in the database and are changed in the admin panel (`/admin/`): FIRMS fetch interval (30 min, 1 h, 3 h, 6 h, 12 h, 1 day, 2 days), weather lookups and OSM tiles per fetch, the Sentinel-2 reuse window, and the triage daily cap, per selection limit, and per scheduled pass. Each has fixed choices or a bounded range; the environment gives the default. Reading needs the verifier token; saving needs the execution code too. | Fetch rate and spend are operator decisions that change during a fire season; a redeploy per change is too slow, and an unbounded field is a spend risk. |
| 34 | The scheduler ticks every 5 minutes and fetches only when the chosen interval has passed since the last fetch (stored in the database), so a new interval applies without a restart. | Rescheduling APScheduler jobs from a request handler would tie settings to one process. |
| 35 | The verifier token is entered once in a header dialog, checked with `GET /api/auth/check`, and kept in localStorage. The header then shows "AI triage ready" with a link to the admin panel. Triage still asks for the execution code each time. | The token unlocks reading and deciding; the code is what spends credit, so it stays a deliberate step. |
| 36 | Each incident view opens with a verification card: four stages (detected, evidence, AI triage, human verifier), a plain headline (not triaged, AI recommendation waiting for a verifier, verified, rejected), and what is still missing with the action that fills it (a report link with the location filled in, Sentinel-2, evidence collection, the AI's own uncertainties). "Verified" means a verifier approved it; the AI never verifies. | Owners and judges could not tell a triaged incident from an untriaged one, or what needs_more_info needed. |
| 37 | A verifier decision can be cancelled. Cancelling appends a `revoke` verdict (with an optional reason); nothing is deleted. Only one decision stands at a time: approving or rejecting again needs a revoke first (HTTP 409 otherwise). Databases from before this change get their verdicts table rebuilt once with the same rows. | The panel kept offering Approve after approval, and approvals stacked up. An append-only history keeps every change auditable. |
| 38 | The agent has a `plan_drone_survey` tool, and verifiers have a Propose button. A proposal is a plan (lawnmower over the hotspots plus 300 m, within 2 km2 and 80 frames at 120 m, with flight time and batteries); it is stored with its source and reason, and only a verifier can approve or reject it. One open proposal per incident. The tool result says it is not an observation, and the prompt forbids citing it as evidence. | The spec flow puts a human between the agent and any flight. No drone is connected, so approval is recorded and waits for a pilot. |
| 39 | OSM fallback: a Geofabrik Indonesia extract reduced to the five feature types the Overpass query asks for (places, main roads, rivers, water, fire stations), lines simplified to about 20 m, packed into SQLite and indexed by the same 0.2 degree tiles (`tools/build_osm_fallback.py`, built on Modal by `tools/osm_fallback_modal.py`). When every Overpass endpoint fails, lookups use it and skip Overpass for 30 minutes. Evidence names the source as the offline extract with its date, and the status bar shows OSM as Offline copy. The server downloads the file once from `OSM_FALLBACK_URL`. | Overpass has been down on every public endpoint for most of the build. A dated offline copy is honest about its age and keeps evidence flowing. |
| 40 | WhatsApp intake is not built: no WhatsApp Business credentials are available. The web form at /lapor stays the citizen channel. | Building against an API without credentials can not be tested. |
| 41 | Manual sharing: a share button on each incident opens a public link `/i/<id>` whose OG tags carry a summary and a static 1200 x 630 image rendered on the server (OSM raster tiles cached 30 days, hotspots colored by FRP, status, nearest settlement, emergency line, attribution). Only incidents the public map shows can be shared, with rounded coordinates and no citizen content. The image is cached until the incident changes. | WhatsApp and Facebook previews need a server-rendered page and image; the dialog shows exactly what others will see. |

| 42 | Evaluation labels count burned ground within 500 m of the cluster's hotspots, not across the whole area of interest. | The area of interest is at least 2 by 2 km. Over a dry season some of it changes for other reasons, and the first labelling run marked all 15 tried clusters burned, including single detections at static heat sources. |
| 43 | NBR treats pixels with NIR plus SWIR2 reflectance under 0.05 as unusable, and reflectance is clipped at 0. Pairs measured before this are measured again when next requested. | Reflectance is DN times 1e-4 minus 0.1, so water and deep shadow go to zero or below and the ratio explodes: dNBR values of 3.7 and 756 were found during labelling. Production hectares measured before 2026-10-28 were affected. |
| 44 | The gate counts Sentinel-2 as independent support for `likely_fire` only when the pair is clear and measured at least 1 ha (25 pixels). | While recording the replay, the agent claimed `likely_fire` with confidence 1.0 for a hotspot whose pair showed 0.28 ha, because any satellite evidence counted. Below 1 ha a dNBR count is within edge and misregistration noise. |
| 45 | Evaluation runs on Muse Spark Open (Baseten) with the production prompt, tools, schema, gate, and critique; the agent gets hotspot, weather, and OSM tools only. | Volume without spending Meta credit, and no leakage: Sentinel-2 is the label source. Muse Spark 1.3 on the same 30 is a separate run on purpose (about $1.65). |
| 46 | Labelling runs on Modal next to the Sentinel-2 COGs in us-west. | From this PC a 10 m block read took about a minute; 768 candidates on Modal took a few minutes. Every window and label is cached, so a change of rule needs no new reads. |
| 47 | Replay mode loads three recorded cases from `replay/incidents/` (one burned, one false positive, one needs more info) as SIMULASI, once, and removes only what it loaded. The recording runs the real pipeline at the time of the case (the Sentinel-2 pair as of 40 days after the first detection) and is retried if the triage fails the schema. | A demo must work with no active fire and no network. Recorded runs do not count as spend. |

| 48 | The drone scene for INC-20261025-0407 was rebuilt on the corrected burn mask: same grid, flight plan, camera, and renderer; only `burned.png` changed (the app's evidence EV-006, cropped to the scene grid). Frames, truth, Glimmer, and SAM were all run again. | The first scene used the mask from before decision 43: inside the survey box 71.15 ha were burned in the scene against 61.02 ha in the corrected mask, so 10 ha (14%) of the scene's burned ground was water or shadow. |
| 49 | The Meta tool loop retries a `previous_response_id` call up to 3 times when the API answers 400 "referenced response not found or expired"; any other error is raised at once. | 4 of 30 evaluation runs got that error seconds after the response was returned, and the same call worked moments later. Production triage uses the same loop. |
| 50 | The replays are recorded with Muse Spark 1.3, the production model. The needs-more-info case is a single nominal hotspot (FRP 4.77 MW) with no clear Sentinel-2 pass since detection. | The first choice for that role (11 hotspots, FRP 39.4 MW, also cloudy) got `possible_fire` from Muse Spark 1.3, a fair call on that data. Re-recording until the model says what the role needs would be cherry picking, so the case was chosen by its data instead and the result kept. |
| 51 | Simulated pilot: an approved plan can be flown by a pilot (a verifier in this prototype). The server simulates telemetry once, deterministically, from the plan and the incident's own weather evidence (cruise 8 m/s, ground speed changed by the wind along each leg, one pack per 25 minutes plus 4% drain per m/s of wind, pack swap at 20% with 5 minutes on the ground), and keeps a sim clock (start time times x10, x30, or x60). The pilot can abort at any time and land only when the route is done. One active plan per incident; a flown plan no longer blocks a new one. | The owner asked to see the drone at work without manual control. A shared sim clock means everyone sees the same flight. No drone is connected, so every view says SIMULASI and a flight over any incident other than INC-20261025-0407 says it has no imagery. Physics simulators reviewed (MuJoCo-Drones-Gym, Crazyflow, CARLA-Air, SkySim, Droneulator) were not adopted: none adds demo value within the remaining days. |

## Day 1 spike results

Run on 2026-10-27 against the live Meta Model API, one call per capability. The key lists `muse-spark-1.3`, `sam-3.1`, `muse-voice-transcribe-1.0`, `muse-wonder-1.0`, and others. Test media: a CC BY 2.0 ground photo of a burned peatland in Indonesia and a public domain NASA satellite image of Borneo smoke (2002), used for testing only and not committed. Spike scripts and raw outputs are kept outside the repo.

| Spike | Result | Decision |
| --- | --- | --- |
| (a) Muse Spark reads a smoke photo | Passed. Structured output: burned ground and background smoke visible, no flames, which matches the photo on inspection. It proposed concepts to segment: "smoke", "burned ground", "charred tree stump". 5.0 s, 578 input and 722 output tokens. | Proceed. Muse Spark picks the SAM concepts from the photo. |
| (b) SAM 3.1 on a ground photo | Mixed. "burned ground" gave one mask over 51% of the frame that follows the ground and excludes stumps and logs precisely (checked visually). "tree stump" found 7 objects (positive control). "smoke", "flames", and "burn scar" returned zero matches; "haze" masked the sky, not the smoke. 1.9 to 3.2 s per call. | Use SAM on photos for burned ground and objects, with concepts chosen by Muse Spark. Do not treat SAM as a smoke detector. An oblique photo has no ground pixel size, so photo masks give a frame fraction, never hectares. |
| (b) SAM 3.1 on a satellite image | Failed. "smoke", "smoke plume", and "cloud" returned zero matches on a MODIS true color image of Borneo smoke. On 2026-10-28, a Sentinel-2 true color window over Merauke (5 October, 10 m) gave zero matches for "burn scar" and "burned area", while dNBR marked 6.7% of the same frame as burned ($0.005 spent). | Spec branch applies: burned area from satellite uses dNBR. Hectares from SAM come only from nadir frames with known ground sampling distance (drone survey). |
| (c) Voice Transcribe with Indonesian audio | Passed. Indonesian is one of the 25 documented languages. A 14.5 s note gave word error rate 0% (30 words, ignoring case and punctuation) from clean WAV and 3.3% after an Opus round trip like a browser recording, in 4.3 s. The audio was synthesized with the Windows Indonesian voice, so field recordings with wind and accents will likely do worse. | Proceed with Muse Voice Transcribe. The endpoint accepts only mono 16-bit PCM WAV at 16 or 24 kHz, so the server converts browser audio with ffmpeg. AssemblyAI is no longer needed as a fallback. |
| (d) Tool calling and structured output | Passed. Muse Spark called `get_weather` and `get_nearby_assets` with the right coordinates, kept `possible_fire` for a hotspot-only incident, cited real evidence IDs in all 5 claims, copied every number from tool results, and wrote an 86-word Indonesian brief. 49.6 s at reasoning effort medium; 3,162 input tokens (753 cached) and 9,048 output tokens (7,831 reasoning). | Proceed. Measured cost is about $0.04 per incident at list prices, mostly reasoning tokens. Re-measure on the real agent. |

As a critic over three claims it caught the planted error ("spreading north" from wind blowing from 58 degrees, which points southwest) and also disputed two claims whose wording went beyond the shortened evidence text ("VIIRS", "nearest"). | Candidate for the critique pass and for evaluation runs, keeping Meta Model API credit for triage.
